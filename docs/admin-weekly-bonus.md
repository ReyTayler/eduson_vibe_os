# Админ-панель и дополнительные токены на текущую неделю

> Архив generation 4: с 7 октября 2026 действует [денежная квота generation 5](credit-policy.md). Старые токеновые показатели и проверки ниже относятся к предыдущей политике.

Адрес: [панель администратора](https://80.249.145.94/admin). Вход отдельный от ученических кабинетов. Создан один аккаунт администратора; выдача прав ученикам и саморегистрация отсутствуют. Начальные реквизиты находятся только в root-only `/var/lib/vibe-os/portal-private/admin-login.json`. Пароль можно изменить в панели; изменение отзывает все admin sessions. Повторный bootstrap не заменяет существующий пароль.

Панель показывает пять учеников: базовый лимит, дополнительные токены, общий лимит недели и доступный остаток. Для выбранного аккаунта можно указать любое положительное целое количество токенов, добавить комментарий и выполнить начисление. Журнал содержит сумму, автора, дату и срок действия. Он сохраняет также прошлые начисления.

Дополнительные токены действуют только в неделе, в которую их выдали. При сбросе в воскресенье в 23:59:00 Europe/Moscow базовая квота снова составляет 1 000 000; бонус не переносится. Admin UI и кабинет ученика обновляют квоту раз в 30 секунд, при возвращении на вкладку и непосредственно на границе недели.

## Выполненное начисление

По прямому запросу владельца student01 начислены **2 000 000** токенов. Базовый лимит 1 000 000 плюс бонус дают **3 000 000** до **11 октября 2026, 23:59 МСК**. На момент проверки подтверждённый расход составлял 829 759, доступный остаток — 2 170 241. Другим ученикам бонус не начислялся.

Операция `f560c880-db32-4932-ac3e-d3e04ca16d54` записана один раз. Проверочный повтор с тем же идентификатором вернул replayed=true. [Приёмка живой панели](../evidence/admin-bonus-acceptance.json). Начисление увеличивает доступный лимит; само по себе токены модели не расходует.

## Учёт и защита

Базовая таблица `weekly_budgets` сохраняет CHECK 1 000 000. Изменять историю расходов или базовую квоту для бонуса не требуется. Новая `weekly_grants` содержит UUID операции, student ordinal, period_start, tokens, actor ID, note и created_at. FOREIGN KEY связывает начисление с существующим недельным bucket. UPDATE и DELETE запрещены SQL-триггерами.

Модельное резервирование и status используют `1_000_000 + SUM(grants текущего student и period_start)`. Резервирование по-прежнему атомарное; подтверждённый расход, cached tokens и незавершённые envelopes учитываются прежним способом. Late settlement относится к исходной неделе. Бонус другого ученика или прошлой недели не увеличивает доступный остаток.

Начисление выполняется в BEGIN IMMEDIATE. Повтор того же UUID с теми же параметрами возвращает прежнюю запись; другие параметры при том же UUID дают конфликт. Сумма положительная, целая и вместе с общим лимитом должна оставаться safe integer. Payload содержит ожидаемое начало недели: если за время отправки началась другая неделя, новая операция отклоняется вместо неожиданного начисления на другой период. Повтор уже записанной операции после сброса возвращает её старый receipt и не создаёт новый бонус.

Browser сохраняет ключ незавершённой отправки в sessionStorage. При сетевом сбое повтор той же формы использует тот же UUID. После подтверждённого сохранения и обновления журналов ключ очищается для следующей намеренной операции. Двойная отправка предотвращается также блокировкой формы до ответа.

Admin sessions используют отдельную таблицу и отдельную cookie `__Host-vibe_admin_session`: Secure, HttpOnly, SameSite=Strict, срок 8 часов. В базе хранится SHA-256 cookie, пароль — Argon2id. Все изменения требуют корректных Origin и CSRF для admin session. Ученическая сессия не считается администраторской. Student ID, actor и недельный scope определяются сервером, поля повышения полномочий из body не принимаются.

## Путь операции

1. React `Admin.tsx` отправляет `POST /api/admin/students/:userId/grants` с tokens, note, requestId, periodStartsAt.
2. `apps/portal/api/admin.mjs` проверяет отдельную admin session, Origin, CSRF и существующего ученика. Его student ordinal извлекается из users, actor — из administrator session.
3. Root workspace broker пересылает запрос по Unix socket в model gateway. Operator capability читается root relay и никогда не возвращается browser или portal API.
4. `/v1/admin/grants` доступен только operator capability. Student capabilities получают 403. Gateway записывает grant в Ledger и возвращает receipt и актуальный бюджет.
5. Broker сбрасывает кэш бюджета выбранного ученика. Все его чаты и проекты сразу используют повышенный лимит. В интерфейсе видны общий лимит и отдельная строка бонуса.

Маршруты чтения: `GET /api/admin/me`, `GET /api/admin/students`, `GET /api/admin/students/:id/grants`. Вход/выход — `POST /api/admin/auth/login` и `/logout`; пароль — `PATCH /api/admin/me`. Public API не предоставляет model keys или operator capability.

## Проверки и эксплуатация

[73 offline tests](../evidence/admin-bonus-tests.tap): прежние 62 регрессии, 10 новых сценариев Ledger/gateway и отдельная приёмка admin API. Проверены граница недели, late settlement, restart, rollback часов, повтор/конфликт UUID, запрет редактирования истории, начисление после исчерпания базы, Origin/CSRF, отдельные роли и отзыв sessions при смене пароля.

[Живая панель](../evidence/admin-bonus-acceptance.json): реальный вход администратора, ровно одно разрешённое начисление student01, повтор UUID, конфликт, CSRF, журнал после reload, desktop/mobile и личный кабинет ученика. Ученические cookies не получают доступ к начислениям и чужим admin budgets. Production usage до/после: 46 запросов, 837 577 подтверждённых токенов, 0 неизвестных резервов; новых model calls в проверках не было.

[Обычная приёмка пяти квот](../evidence/weekly-quota-acceptance.json) адаптирована к текущему base+bonus и также прошла. [Проверка секретов](../evidence/student-secret-scan.json) дополнена паролем нового администратора.

`apps/portal/tests/admin-bonus-live.mjs` — архив конкретной разрешённой операции, **не общий health check**. Он использует сохранённый root-only intent с постоянным UUID; повтор восстанавливает ту же операцию. Для новых начислений используется панель. Нельзя создавать новый intent или менять amount ради повторного теста на живых аккаунтах.

Копии portal и model budget до деплоя лежат в root-only `/var/lib/vibe-os/operator-snapshots/admin-weekly-grants-20261006/`. При восстановлении нельзя заменять рабочую базу старой копией поверх последующих расходов и начислений.
