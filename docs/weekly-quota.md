# Личные недельные квоты

Обновление опубликовано 6 октября 2026 года на https://80.249.145.94/. У каждого из пяти кабинетов независимый лимит **1 000 000 токенов в неделю**, общий для всех его проектов и чатов. Ключи API не определяют владельца квоты. Совокупный недельный допуск пяти учеников — до 5 000 000 токенов.

## Время и смысл сброса

Граница — **каждое воскресенье, ровно 23:59:00, Europe/Moscow**. Текущая неделя: с 4 октября 2026 года 23:59 МСК включительно до 11 октября 23:59 МСК исключительно. Следующий сброс — **11 октября 2026 года 23:59 МСК** / `2026-10-11T20:59:00.000Z`.

Неиспользованные токены не переносятся. До границы применяется старый недельный bucket; с самой границы — новый лимит 1 000 000. Никакого удаления истории расхода или cron, обнуляющего общую таблицу, нет. Gateway вычисляет календарное окно при status/admission, поэтому новый лимит доступен после простоя или перезапуска. Серверный timezone и timezone браузера не меняют правила.

Для завершившегося после воскресной границы запроса фактический usage применяется к неделе его первоначального допуска. Незавершённый или неизвестный запрос сохраняет резерв в этой же старой неделе. Успешное завершение старого запроса не увеличивает доступный лимит новой недели.

Gateway сохраняет максимальное принятое начало периода. Если системные часы откатились в более раннюю уже пройденную неделю, admission блокируется до восстановления времени; нельзя повторно получить прошлый лимит переводом часов.

## Учёт и миграция

`services/model-gateway/ledger.mjs` содержит production `Ledger` generation 4 и отдельный `LegacyLedger` для регрессий предыдущей схемы.

SQLite WAL/FULL, foreign keys и BEGIN IMMEDIATE сохраняются. Новые таблицы:

- `weekly_policy`: версия 4, timezone, максимальный принятый период.
- `weekly_budgets`: студент, начало/конец периода, CHECK лимита 1 000 000; составной PRIMARY KEY(student, period_start).
- `request_scopes`: уникальный request_id, владелец и неизменный период. JOIN с model_requests даёт расход отдельного ученика.

Reserve атомарно проверяет дедупликацию ID, состояние защиты, принадлежность периода и его остаток; сохраняет запрос и scope одной транзакцией. Одновременные проекты одного кабинета используют один счётчик. Идентификаторы запросов остаются уникальными даже между учениками и неделями. Settlement однократный, только для состояния sent.

Перед upstream резервируется `max(131072, requestUtf8Bytes + 32768 + max_tokens)`. В расход входят input/output и cache usage согласно действующему codec gateway. Подтверждённый terminal usage заменяет резерв; cancel/error/crash/incomplete оставляет полный envelope. Остаток должен покрыть резерв нового вызова, поэтому новый запрос может стать недоступен раньше, чем подтверждённый расход достигнет ровно миллиона. В настройках отдельно видны подтверждённые токены, резерв и доступный остаток. Входящие и исходящие токены расходуются из одного лимита; reasoning входит в output. Предыдущий протокольный fail-closed breaker при недостоверном oversized usage сохраняется.

Миграция добавляет scopes к существующим gen3-запросам, не меняя их ID, state, debit и usage. Исторические credential 20–24 однократно привязаны к ученикам 1–5, период определяется по исходному created_at. 25–27 относятся к операторскому бюджету. Уже сопоставленные запросы при рестарте не перераспределяются.

На момент публикации сохранены **31 прежний запрос, 240 599 подтверждённых токенов, 0 неизвестных резервов**. Расход текущей недели ученика01 — 232 781, ученика05 — 7 704; у учеников02–04 по 19 токенов прежних коротких canary. Операторский исторический расход — 57 токенов. Новые платные проверки не выполнялись.

Операторские canary имеют отдельный lifetime лимит 1 000 000. Они не уменьшают ученические недельные квоты. `operator.mjs status` возвращает operator budget в `budget`, общую историю в `overview.lifetime`, личные текущие квоты в `overview.students`. Старый глобальный gen3 cap для работы учеников заменён.

Root-only SQLite backup до изменения: `/var/lib/vibe-os/operator-snapshots/weekly-quota-20261006/budget-before.sqlite`. Старую backup нельзя восстанавливать поверх появившихся после неё платных записей.

## Идентификация и провижининг

В `/etc/vibe-os/credentials/student-capabilities.json` root mode 0400 находятся пять различных opaque capability, привязанных к номерам учеников. Systemd передаёт gateway этот файл через LoadCredential. Capability не содержат API ключей и не передаются браузеру.

Gateway определяет student по предъявленной capability. Чужой X-Vibe-Credential возвращает 403 до reserve/upstream. Студенческий GET /v1/status возвращает только собственную квоту: без списка ключей, операторского бюджета или чужой истории. Старый общий operator capability отозван; новая operator capability остаётся у оператора и никогда не выдаётся ученическим engines.

Root broker записывает собственную capability ученика в model-capability каждого нового проекта. У трёх существовавших на момент публикации проектов файлы заменены атомарно с сохранением владельцев и mode 0400. Школьный SDK и NsJail mount используют прежний защищённый путь /model-capability.

Portal получает student из проверенной серверной сессии и передаёт его в typed broker request. Значение из query/body браузера не используется для выбора чужого бюджета. Broker хранит отдельный cache/pending для каждого студента, TTL 1 секунда, с обязательной инвалидизацией при достижении resetsAt.

Текущая provisioned схема поддерживает именно пять существующих пользователей. Расширение регистрации требует выдавать новую capability и убирать фиксированное ограничение 1..5 согласованно в ledger/gateway/broker. Не следует создавать шестого пользователя только SQL-вставкой.

## Интерфейс

В настройках показаны личные остаток, лимит за неделю, подтверждённый расход, резерв при его наличии и следующий сброс с отметкой МСК. UI обновляет статус каждые 30 секунд, при возврате вкладки и сразу после resetsAt. Асинхронный результат старой пользовательской сессии не переносится в новый кабинет.

Редактор и сохранение файлов доступны после исчерпания квоты. Модель и параметры сохранены: deepseek-flash, Off/Low/High/Max, max_tokens=65536 на вызов. Пароли, чаты, человеческие проекты и опубликованные сайты сохранены.
