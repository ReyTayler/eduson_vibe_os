# Исправление CONTENT_LIMIT при работе Harness с файлами

6 октября 2026 года запрос в проекте «2д подзмелье рыцарь» завершился с ошибкой в 22:29:36 МСК. Модель успела выполнить десять шагов и восемнадцать операций с инструментами. Перед одиннадцатым шагом школьный gateway отклонил историю как `CONTENT_LIMIT`.

Причина установлена по защищённому журналу native Harness: `turn/end` содержит `School gateway: CONTENT_LIMIT`. Ошибка воспроизведена офлайн на истории этого же чата через неизменённый serializer из закреплённой версии DeepSeek Harness. В истории оказалось 21 сообщение и 72 content blocks, включая вложенный текст tool results. Предыдущий валидатор разрешал суммарно только 64 блока.

Реконструированная история занимала 158 473 UTF-8 байта без tool declarations. Ограничение входного тела составляет 524 288 байт; причина остановки была в количестве блоков. На момент диагностики остаток ученика01 составлял 446 969 токенов при недельной квоте 1 000 000. Отклонённый одиннадцатый вызов не дошёл до провайдера: в gateway проверка формы тела выполняется до резервирования и отправки upstream.

Подробности: [диагностика и повтор старого отказа](../evidence/model-history-diagnosis.json).

## Изменения

| Участок | Было | Стало |
| --- | --- | --- |
| Суммарные content blocks | Максимум 64 | Ограничение количества удалено |
| Блоки в одном массиве content | Максимум 16 | Ограничение количества удалено |
| Сообщения в запросе | Максимум 32 | Ограничение количества удалено |
| Причина в broker | Любая native ошибка превращалась в MODEL_RUN_FAILED | Причины сопоставляются с проверенным списком безопасных кодов |
| Ошибка в интерфейсе | Общий совет создать новый чат | Отдельные тексты для квоты, объёма истории, частоты, соединения и отклонения запроса |

Форма JSON, допустимые роли и типы блоков, глубина content, перечень инструментов и максимальный размер входного тела продолжают проверяться. Обработка массивов ограничена общим размером тела, поэтому количество небольших блоков больше не останавливает обычную работу с инструментами.

Новый `services/workspace-broker/run-errors.mjs` принимает только известные причины. HTTP-отказ адаптер возвращает как `School gateway: CODE`. Закреплённый upstream SSE parser передаёт код gateway_error без этого префикса; сопоставление учитывает обе формы. Неизвестные сообщения не передаются в публичный API или служебную строку диагностики. В журнале broker остаются run ID и два безопасных кода.

Общий совет начинать новый чат убран из сообщения `MODEL_RUN_FAILED`. Рекомендация нового чата появляется при подтверждённом ограничении размера запроса или защищённого журнала. Недельная квота и её воскресный сброс не менялись.

## Проверка

[62 offline regression tests](../evidence/model-history-tests.tap) прошли: прежние проверки gateway, weekly ledger и response admission дополнены историей с 81 сообщением, массивами более 16 блоков, большим количеством tool results и проверкой безопасных причин отказа. Переход на длинную историю не обходит byte guard или недельное резервирование.

[Сценарий через настоящий Harness и браузер](../evidence/model-history-harness.json) использует отдельный временный gateway с локальными ответами провайдера и только собственный временный проект ученика05. Проверено:

- двадцать шагов инструментов, сорок успешных чтений файлов и итоговый ответ;
- запрос с 41 сообщением и 161 content blocks, reasoning High и сохранение подписей;
- перезапуск движка и продолжение того же чата;
- HTTP 429, разрыв SSE и исчерпание недельной квоты с правильными кодами и русскими сообщениями;
- сохранение диалога и сообщений об ошибках после обновления страницы.

Fixture удалён. Реальный DeepSeek не вызывался: production ledger до и после содержит 41 запрос, 560 849 подтверждённых токенов, 0 неизвестных резервов.

[Проверка исходного чата ученика01](../evidence/model-history-live-check.json) подтвердила native resume, отсутствие maxSteps, доступный ввод и актуальную подпись «По квоте». Содержимое workspace и пользовательские/ассистентские сообщения совпадает с сохранёнными контрольными значениями. Исходный native journal сохранён целиком как неизменённый префикс; штатное открытие сессии добавило только служебный `session/end-seed`.

В исходном диалоге изменена только системная плашка. Запись run сохранила состояние failed и прежние timestamps; код ошибки уточнён до `MODEL_HISTORY_REJECTED`. Резервная копия базы до исправления хранится в root-only `/var/lib/vibe-os/operator-snapshots/history-failure-20261006/portal-before.sqlite`. Историю расходов не переписывали. Автоматического повторного платного запроса в ученическом проекте не запускали.

## Границы

История не становится бесконечной: входной UTF-8 запрос ограничен 512 КиБ, модель имеет своё контекстное окно, protected native journal ограничен 96 МиБ. Эти границы теперь отделены от ошибки количества блоков. Длинный чат также расходует входные и cached tokens при следующих вызовах; недельная квота учитывает все такие вызовы.

Для продолжения достаточно обновить интерфейс через Ctrl+F5 и отправить следующий запрос в том же чате. Платформа доступна по [рабочему адресу](https://80.249.145.94/).
